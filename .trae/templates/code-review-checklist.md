# 代码审查检查清单

> 基于最小化变更原则、原子性修改要求和可追溯性规范的代码审查指南
> **版本: 1.0.0 | 更新: 2026-04-26**

---

## 📋 审查前准备

### 审查者要求
- [ ] 理解本次变更的业务需求
- [ ] 熟悉相关代码模块
- [ ] 了解项目代码规范

### 环境准备
```bash
# 1. 获取最新代码
git fetch origin

# 2. 查看变更范围
git diff origin/main...HEAD --stat

# 3. 查看详细变更
git diff origin/main...HEAD

# 4. 查看提交历史
git log origin/main...HEAD --oneline
```

---

## 1. 最小化变更原则审查

### 1.1 单一职责检查
- [ ] 每个提交只包含单一功能或修复
- [ ] 提交粒度适当，便于理解
- [ ] 无无关变更混入

### 1.2 可回滚性检查
- [ ] 每个提交可独立回滚
- [ ] 回滚不会破坏其他功能
- [ ] 回滚后项目仍能编译

### 1.3 提交粒度评估
| 评估项 | 标准 | 结果 |
|--------|------|------|
| 功能完整性 | 每个提交实现完整功能点 | ☐ |
| 独立性 | 提交之间无强依赖 | ☐ |
| 可理解性 | 变更范围清晰明确 | ☐ |

### 1.4 常见问题
```markdown
❌ 问题: 一个提交包含多个功能
✅ 建议: 拆分为多个独立提交

❌ 问题: 修复Bug的同时重构代码
✅ 建议: 先修复Bug，再单独提交重构

❌ 问题: 提交包含格式化变更
✅ 建议: 代码格式化单独提交
```

---

## 2. 原子性修改要求审查

### 2.1 单文件修改检查
- [ ] 每个提交尽量只修改一个文件
- [ ] 跨文件变更有明确的依赖顺序
- [ ] 无未使用的导入或代码

### 2.2 文件变更分析
```bash
# 查看每个提交修改的文件数
git log --pretty=format:"%h %s" --name-only

# 检查文件变更统计
git diff --stat
```

### 2.3 变更范围评估
| 提交 | 修改文件数 | 评估结果 | 建议 |
|------|------------|----------|------|
| | | ☐ 符合<br>☐ 需改进 | |

### 2.4 代码整洁度检查
- [ ] 无未使用的导入语句
- [ ] 无未使用的变量或方法
- [ ] 无调试代码或注释掉的代码
- [ ] 无与功能无关的变更

---

## 3. 可追溯性规范审查

### 3.1 提交信息检查
- [ ] 提交信息符合规范格式
- [ ] 类型标识正确（feat/fix/docs等）
- [ ] 描述清晰简洁（不超过50字符）
- [ ] 详细说明完整（如有必要）

### 3.2 提交信息格式验证
```markdown
格式: <type>(<scope>): <subject>

✅ 正确示例:
feat(level): 添加玩家等级系统
fix(scheduler): 修复内存泄漏问题
docs(api): 更新API使用文档

❌ 错误示例:
update: 一些修改
fix bug
添加功能
```

### 3.3 关联信息检查
- [ ] 关联了相关Issue（如适用）
- [ ] 引用了相关文档
- [ ] 说明了破坏性变更（如有）

### 3.4 文档同步检查
| 文档类型 | 需要更新 | 已更新 | 检查项 |
|----------|----------|--------|--------|
| 代码注释 | ☐ | ☐ | JavaDoc/KDoc完整 |
| API文档 | ☐ | ☐ | 接口变更已记录 |
| 配置文件 | ☐ | ☐ | 配置示例已更新 |
| 更新日志 | ☐ | ☐ | CHANGELOG.md已更新 |
| 修复记录 | ☐ | ☐ | 修复记录已创建 |

## 6. 审查意见记录

### 6.1 问题分级
| 级别 | 说明 | 处理方式 |
|------|------|----------|
| 🔴 **阻塞** | 必须修复才能合并 | 要求修复后重新审查 |
| 🟡 **建议** | 建议改进但非必须 | 可以后续优化 |
| 🟢 **疑问** | 需要澄清的问题 | 等待回复 |
| 🔵 **赞赏** | 值得肯定的实现 | 给予鼓励 |

### 6.2 审查意见模板

#### 阻塞问题
```markdown
🔴 **阻塞**: [问题描述]

**位置**: [文件路径:行号]

**问题**: [详细描述]

**建议**: [改进建议]

**原因**: [为什么这是问题]
```

#### 改进建议
```markdown
🟡 **建议**: [建议描述]

**位置**: [文件路径:行号]

**当前实现**: [当前代码]

**建议改进**: [改进方案]

**收益**: [改进后的好处]
```

#### 疑问澄清
```markdown
🟢 **疑问**: [问题描述]

**位置**: [文件路径:行号]

**问题**: [需要澄清的内容]
```

#### 肯定赞赏
```markdown
🔵 **赞赏**: [赞赏内容]

**位置**: [文件路径:行号]

**说明**: [为什么值得赞赏]
```

## 8. 审查工具命令

### 8.1 Git审查命令
```bash
# 查看提交历史
git log --oneline --graph

# 查看文件变更
git diff [commit1] [commit2]

# 查看某文件的变更历史
git log -p [文件路径]

# 查看某行的变更历史
git blame [文件路径]

# 查看统计信息
git diff --stat
```

## 9. 快速参考

### 9.1 提交类型速查
| 类型 | 使用场景 | 示例 |
|------|----------|------|
| feat | 新功能 | feat: 添加等级系统 |
| fix | Bug修复 | fix: 修复内存泄漏 |
| docs | 文档 | docs: 更新API文档 |
| style | 格式 | style: 统一缩进 |
| refactor | 重构 | refactor: 优化查询 |
| perf | 性能 | perf: 减少查询次数 |
| test | 测试 | test: 添加单元测试 |
| chore | 工具 | chore: 更新配置 |

### 9.2 审查优先级
1. 🔴 阻塞问题 - 必须修复
2. 🟡 建议改进 - 尽量采纳
3. 🟢 疑问澄清 - 及时回复
4. 🔵 肯定赞赏 - 给予鼓励
